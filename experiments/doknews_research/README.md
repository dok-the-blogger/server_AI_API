# Ручной пилот API-исследователя dok.news

Пилот готовит исследовательское досье через OpenAI API для последующего разбора
редактором в ChatGPT. Он нужен, чтобы проверить качество источников, сохранение
оговорок, полезность кандидатов и фактический расход API на одном проходе.

Это отдельный эксперимент. Его запуск не требует выкладки dok.news, обновления
радара или изменения действующих задач. Исследователь получает веб-поиск и
переданный снимок фактуры; доступ к DOK MCP автоматически из ChatGPT не переносится.
Сайт, память, решения радара и расписания в этом пилоте не изменяются.

## Файлы

- `pilot.py` — подготовка и ручное управление одной API-сессией.
- `START.cmd`, `run-pilot.ps1`, `launcher.py`, `bootstrap.py` — локальный запуск на Windows с
  отдельным окружением и безопасным выбором файла ключа.
- `requirements-pilot.txt` — отдельные зависимости пилота; production requirements
  сервиса не заменяются.
- `dossier_contract.md` — роль исследователя и формат проверяемого досье.
- `input.example.json` — пустой шаблон снимка, а не реальные данные и не доказательство
  отсутствия новостей или дублей.

Полный `doknews-editor` в этот каталог и в Git не копируется. `prepare` получает
его из отдельно указанного каталога навыка. Фактический снимок, подготовленный
пакет, результаты и данные сессии храните в приватном каталоге запуска вне Git.

В каталоге запуска создаются:

| Файл | Содержимое |
| --- | --- |
| `request.json` | Подготовленный API-запрос с инструкциями и снимком исходных данных. |
| `manifest.json` | Модель, состав пакета, хеши входов, время снимка и описание покрытия. |
| `receipt.json` | Состояние запуска, известные ID сессии/хода, сведения об отмене и доступный usage. |
| `dossier.md` | Итоговый текст после подтверждённого завершения хода; при незавершённой работе может отсутствовать. |

Пилот не сохраняет API-ключ в этих файлах. `request.json` содержит приватные
исходные материалы и полный переданный пакет инструкций; не добавляйте каталог
запуска в Git.

## Подготовка окружения

Нужны Python 3.11 или новее и отдельное виртуальное окружение. Из каталога этого
эксперимента:

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-pilot.txt
```

Для Windows удобнее launcher ниже; активация окружения ему не требуется.
Зависимость клиента API закреплена в `requirements-pilot.txt` как `openai==3.49.0`;
`socksio>=1.0.0,<2` добавляет поддержку существующих SOCKS-прокси. Проверки
используют стандартный `unittest`, имитацию клиента и реальный SDK 3.49.0 с
`httpx2.MockTransport`: внешних API-запросов и настоящего ключа в них нет.
Первый запуск Windows launcher прошёл offline-проверку пакета и остановился при
создании окружения, до выбора ключа. Живой API-запуск ещё не выполнен. Эти проверки
не подтверждают доступность API или модели в конкретном аккаунте.

Ключ передаётся только переменной окружения `OPENAI_API_KEY`. Загрузите скачанный
ключ безопасным способом в окружение запуска. Не вставляйте его в этот README,
команду, которая попадёт в историю оболочки, JSON-снимок, Git, чат или журнал.
Скачанный файл с ключом не является входным файлом пилота.

## Готовый запуск на Windows

Для заранее подготовленного пакета достаточно открыть `START.cmd` в Проводнике.
Файлы `START.cmd`, `run-pilot.ps1`, `launcher.py`, `bootstrap.py`, `pilot.py` и
`requirements-pilot.txt` должны лежать рядом, а `request.json`, `manifest.json` и
`receipt.json` — в подкаталоге `prepared-run`. Требуется установленный Python 3.11
или новее. Активация окружения вручную не нужна.

Launcher выполняет шаги в таком порядке:

1. Проверяет подготовленный пакет без обращения к API: хеши, ID запуска, состояние
   receipt, разрешённые инструменты, модель и согласованный порог расходов.
2. Проверяет свежесть снимка: для нового исследования допускается возраст до шести
   часов. Устаревший снимок нужно собрать и подготовить заново; смена даты без
   обновления исходных данных не делает его актуальным.
3. Через `bootstrap.py` создаёт или достраивает `.venv` рядом со скриптом и устанавливает зависимости из
   `requirements-pilot.txt`, включая OpenAI SDK 3.49.0 и поддержку SOCKS. Ключ ещё
   не запрашивается и не передаётся процессам установки. Настройки прокси не меняются.
4. Открывает стандартный диалог выбора скачанного файла ключа. Файл читается только
   на этом компьютере; его имя и содержимое не выводятся. Допускается один ключ
   в небольшом текстовом или JSON-файле. Отмена диалога прекращает запуск.
5. Повторно проверяет пакет и начинает один проход. Ключ передаётся только в
   `OPENAI_API_KEY` дочернего процесса Python, без аргументов командной строки,
   сохранения в системное окружение, журнал или файлы пилота.

Bootstrap отдельно выполняет `venv --without-pip`, проверяет Python 3.11+ и точное
совпадение `sys.prefix` с целевой `.venv`, затем запускает `ensurepip --upgrade`,
установку закреплённых зависимостей и проверку SDK. Частично созданный каталог
сохраняется; `--clear`, удаление окружения и установка в системный Python не используются.
При сбое до выбора ключа создаётся `bootstrap-diagnostics.json` рядом со скриптами:
этап, код возврата, тип исключения/Windows-код и ограниченные очищенные stdout/stderr.
Проверка окружения также сохраняет версию, путь интерпретатора, prefix/base_prefix
и наличие модуля ensurepip. Окружение процесса, аргументы команд и файлы ключа туда
не записываются. Ключи, Bearer-значения, credentials в URL и query-параметры маскируются.
Этот журнал не добавляется в Git. Ошибка записи журнала не меняет исходный сбой.
Разделение стадий помогает достроить окружение или установить точную причину
ошибки ensurepip; устранение первопричины до следующей проверки не подтверждено.

Порог `spend_limit_cents` показывается перед выбором ключа. Этот launcher допускает
до **300 центов ($3)** на первую сессию и сверяет значение с запросом, manifest и
receipt. Это настройка остановки в API, а не обещание точной итоговой суммы счета.
Действует также клиентский срок наблюдения 900 секунд; возможности и ограничения
отмены описаны ниже.

После создания процесса локальная копия его переменной ключа удаляется из объекта
запуска, а ссылки на ключ очищаются при выходе. Исходный скачанный файл остаётся
у владельца. Скрипт не гарантирует физическое стирание всех копий строк из памяти.

Повторное открытие `START.cmd` с уже отправленным пакетом не создаёт вторую сессию
и останавливается **до запроса ключа**. Для чтения результата существующей сессии
из каталога пакета используйте:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\run-pilot.ps1 -Action resume
```

`-Action status` читает состояние, `-Action cancel` запрашивает остановку. Если
выбор файла неудобен, параметр `-KeyMode Prompt` включает скрытый ввод ключа:

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\run-pilot.ps1 -KeyMode Prompt
```

Для другого подготовленного каталога предусмотрен `-RunDir 'D:\path\to\run'`.
Ключ не нужно вставлять в эту команду. `ExecutionPolicy Bypass` относится только
к запускаемому процессу PowerShell; настройки CurrentUser/LocalMachine и групповые
политики скрипт не меняет. Новые задачи планировщика не создаются.

Инструменты DOK Studio для передачи файлов не исполняют Python или PowerShell.
При отсутствии отдельного канала выполнения пользователь должен локально открыть
launcher один раз. Загрузка файлов сама по себе не означает, что окружение
установлено или платный проход уже начался.

## Снимок исходных данных

Скопируйте `input.example.json` в приватный каталог вне репозитория и заполните
проверенными данными. `captured_at` — время сборки снимка в ISO 8601 с часовым
поясом, например `2026-11-12T16:00:00Z`; замените дату на фактическую.
`task` задаёт название прохода, тему и окно свежести в часах.

В `coverage.archive`, `coverage.radar` и `coverage.memory` используйте:

| Значение | Значение для исследователя |
| --- | --- |
| `not_provided` | Данные этого вида не предоставлены. Пустой список ничего не доказывает. |
| `partial` | Передана часть данных; границы и пропуски описаны в `coverage.missing`. |
| `complete` | Полностью передана явно описанная выборка. Это не означает покрытие всего архива или всей памяти. |

В `coverage.missing` описывайте границы запросов и известные пробелы: темы,
период, лимит, непройденную пагинацию, отсутствующие оригиналы, неизвестные версии,
недоступные источники. Даже при `complete` укажите, какая именно выборка полна.

Массивы должны сохранять происхождение материалов. При заполнении полезны:

- `radar_signals`: ID и версия сигнала, источник и прямая ссылка, заголовок/текст,
  дата публикации источника, время обнаружения, признак усечения текста.
- `archive_articles`: канонический ID статьи и версия, URL, заголовок, дата,
  прочитанный полный текст либо явно обозначенные карточка/TL;DR, время чтения.
- `memory_records`: ID и ревизия записи, заголовок, прочитанный текст либо
  карточка, источники, ожидание/срок возвращения, время чтения.

Не помечайте TL;DR как полный текст и не подставляйте предполагаемые версии.
Отсутствие доступа обозначайте явно. Ссылки на источники в этих записях — данные;
они не дают API-агенту разрешений на изменение внешних систем.

## Подготовить один проход

Из каталога эксперимента, подставив действительные пути:

```bash
python pilot.py prepare \
  --skill-dir /private/skills/doknews-editor \
  --snapshot /private/doknews-pilot/input.json \
  --run-dir /private/doknews-pilot/run-001
```

Для прохода, в котором главное явление — ИИ или предполагаются существенные
выводы о его способностях и последствиях, добавьте `--include-ai-guide`.
Без руководства исследователь должен обозначить зависимую оценку `needs_context`
и запросить недостающие инструкции.
Каталог `--skill-dir` должен содержать актуальный пакет `doknews-editor`.
`prepare` собирает только исследовательскую фазу 1; подготовка текста и выбор
заголовка/угла в этот проход не входят. Это ещё не платное исследование.

Перед `run` просмотрите подготовленные материалы: тему, окно времени, актуальность
инструкций, границы снимка и отсутствие секретов. Пример с пустыми массивами
может показать работу веб-исследования, но не проверяет интеграцию с архивом,
радаром и памятью dok.news.

## Запуск и продолжение

```bash
python pilot.py run --run-dir /private/doknews-pilot/run-001 --max-seconds 900
python pilot.py status --run-dir /private/doknews-pilot/run-001
python pilot.py resume --run-dir /private/doknews-pilot/run-001
```

Модель по умолчанию — `gpt-6-astra`. Используется одна сессия, исполняемая на
платформе OpenAI, с веб-поиском. `run` начинает платную работу. Сохранённый каталог
запуска связывает последующие действия с той же сессией. После обрыва соединения
сначала проверьте `status`. Команды `status` и `resume` только читают состояние
и готовый итог существующей сессии через GET-запросы. Они не отправляют нового
сообщения модели, не начинают новое исследование и не возобновляют генерацию.

Если в `receipt.json` записано `creation_unknown` и ID сессии неизвестен,
остановитесь и проверьте сессии вручную в OpenAI Platform. Не повторяйте `run`
и не создавайте новый `--run-dir` для того же запроса, пока исход создания
не установлен. Отсутствие ответа не означает, что платная работа не началась.

Для запроса остановки:

```bash
python pilot.py cancel --run-dir /private/doknews-pilot/run-001
```

При сетевой ошибке наблюдателя с уже известным ID пилот также запрашивает отмену:
он не оставляет продолжающуюся облачную работу без своего таймера. Отправка отмены
не доказывает её завершение; `status` проверяет фактический исход. Если работа успела
завершиться до отмены, `resume` заберёт её досье. Если ID сессии получить не удалось,
исход остаётся `creation_unknown` и требуется проверка сессий в Platform.

После проверки и сохранения результата можно удалить сессию:

```bash
python pilot.py close --run-dir /private/doknews-pilot/run-001
```

`close` разрешён после подтверждённого terminal-исхода; для `completed` требуется
сохранённое досье. Очистка облачной среды после удаления асинхронная. До удаления
сессия сохраняется для проверки результата и трассировки. При отсутствии итогового
`final_answer` receipt отмечает `missing_final`; промежуточный commentary его не заменяет.

`--max-seconds 900` задаёт клиентский срок наблюдения: по его истечении локальный
наблюдатель пытается запросить отмену. Этот механизм действует только пока
наблюдатель `run` работает и ему известен ID сессии. Он не является серверным
дедлайном. После остановки наблюдателя автоматическая отмена не гарантируется.

Запрос передаёт серверный `spend_control.limit`, по умолчанию **300 центов ($3)**,
и `agent.service_tier="default"`. При достижении порога API может остановить сессию
с `session_budget_exceeded`. Данные расхода в ответе — предварительные, с
округлением до целых центов; настройка не гарантирует точную итоговую сумму счета.
Отдельного жёсткого ограничения числа токенов пилот не задаёт.
Отмена выполняется по возможности API и соединения, не возвращает стоимость
уже выполненной работы и не считается подтверждённой только по отправке запроса.
Прерывание локальной команды само по себе не доказывает остановку удалённой
сессии; проверяйте её итоговый статус.

## Что принимать по результату

Локальные проверки протокола:

```bash
python -m unittest -v
```

Сейчас проходят 30 offline-тестов: 17 проверок пилота и контракта реального SDK,
6 проверок Windows wrapper на Python и 7 проверок bootstrap. В последнюю группу
входит реальный локальный подпроцесс с большими stdout/stderr: проверяются
дренирование обоих потоков, ограничение размера, маскировка и сохранение кода ошибки.
Обновлённый bootstrap и диалог выбора ключа на Windows пока не проверены.
Тесты проверяют повторную отправку после неизвестного исхода, отмену
при разрыве наблюдения, пагинацию сохранённых items, различение final/commentary
и сохранность последнего известного usage. Wrapper дополнительно проверяет
свежесть и целостность пакета, запрет повторной отправки и согласованный порог
расходов. Нулевое или отсутствующее usage не
следует интерпретировать как бесплатный запуск; данные предварительные.

Досье должно содержать до трёх кандидатов, проверяемые источники ключевых
утверждений, связанную предысторию с версиями, причины отклонения альтернатив,
границы покрытия и конкретные вопросы редактору. Полный формат — в
`dossier_contract.md`. Если достойных кандидатов меньше, заполнять список не нужно.

Проверьте, сохранил ли исследователь важные оговорки, отличил ли дату события от
даты пересказа и не объявил ли отсутствие дублей по частичному пакету. Затем
оцените, какую часть исследования пришлось повторить здесь. Именно это вместе
с фактическим API usage позволит оценить пользу переноса. Текст ответа модели
не является источником достоверных данных о собственном биллинге.

Результат пилота — исследовательское досье. Окончательный угол, допуск к
публикации, свежая проверка общего архива и черновиков, подготовка статьи и её
публикация остаются отдельной редакторской работой. Запуск пилота не создаёт
нового расписания и не отключает существующие задачи ChatGPT.
